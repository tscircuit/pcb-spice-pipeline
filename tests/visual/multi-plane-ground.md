## Extraction design boundary

The reference via physically touches all three planes. Choosing one target would discard two return paths. Removing the target-count check is insufficient: the current `Path` ends at one plane, the FastHenry writer joins only that endpoint to a plane mesh, and the other meshes are left without those barrel contacts. The same-pour check also rejects references connected via different planes. FasterCap puts all ground pours and reference paths into one conductor, including same-net islands without verified physical connectivity. Treating a net name as proof of a physical connection would therefore make its return conductor inconsistent with the FastHenry network.

A supported model needs a physical connectivity graph of eligible ground copper and contacts, with each reference barrel split at every validated plane contact and each contact connected to its corresponding FastHenry mesh. Any inter-plane stitching included in the extraction needs the same treatment. FasterCap conductor grouping must follow physical connectivity, including disconnected same-net islands. Validation must resolve the same net and actual barrel span, dimensions and full contact with the pour, and reject ambiguous, wrong-net, out-of-span, edge/cutout, or disconnected cases. The current model also intentionally omits other ground routing, stitching, package/PDN impedance and unused via stubs; their inclusion or exclusion must be explicit. A fix should test those cases and compare generated connectivity and solver behavior, not only verify that deck generation succeeds.
